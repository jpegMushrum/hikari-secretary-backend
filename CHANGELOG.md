# История изменений

Все значимые изменения фиксируются в этом файле.

## [0.3.5] — 2026-11-22

- Bot API возвращает ближайшие мероприятия со статусом записи для участника
  и ссылкой на опубликованный анонс, если она известна. Участник может
  изменить напоминание действующей регистрации.
- Admin API сохраняет настройку ежедневной генерации ИИ в PostgreSQL.
  Отключение автогенерации сохраняет сегодняшний пост. Отдельное действие
  снимает с отправки последний ИИ-пост в очереди и сохраняет настройку
  автогенерации.
- Admin API ставит новую генерацию материала в очередь с сохранёнными
  настройками. У ожидающего поста сохраняются время отправки и цели,
  а при пустой очереди создаётся новое задание.

## [0.3.4] — 2026-11-21

- Если DeepSeek завершил ответ пустым или повреждённым JSON, backend один раз
  запрашивает материал заново перед записью ошибки задания.

- Admin API отдельно возвращает последнее задание ИИ и принимает запрос на
  его замену независимо от фильтров, сортировки и пагинации истории. Можно
  повторить генерацию после ошибки или обновить материал запланированной
  публикации до начала доставки с сохранением времени отправки и целей.
- Миграция 010 сохраняет последний доступный материал каждого задания
  как первую версию. При изменении материала добавляется следующая версия.
  Admin API возвращает число версий и отдельный постраничный список материалов.
- При генерации backend проверяет темы разговора и лексики по всем
  сохранённым версиям. DeepSeek получает частоты употребления слов и
  грамматических конструкций из той же истории.

## [0.3.3] — 2026-11-20

- Admin API возвращает отдельное задание истории ИИ по ID. В карточке и
  списке доступен текущий статус связанной публикации. Список поддерживает
  сортировку по этому статусу.
- Генератору передаётся требование писать название темы на японском.
  Сортировка истории ИИ по названию использует исходное название публикации.

## [0.3.2] — 2026-11-19

- Admin API поддерживает сортировку по всем колонкам списков мероприятий,
  черновиков, участников, публикаций, отзывов и истории ИИ.

## [0.3.1] — 2026-11-19

- Импортёр SQLite собирается отдельно из `Dockerfile.import-legacy`.
  Runtime-образ backend содержит API и мигратор.
- Поиск мероприятий и черновиков в административном API учитывает ID записи.
  Черновик можно найти по ID публикации или ID связанного мероприятия.
- Поиск людей поддерживает Telegram username с `@`, внутренний и Telegram ID.
- Поиск отзывов поддерживает название и ID мероприятия, данные автора и
  ID отзыва. Точные фильтры по мероприятию и автору можно сочетать с поиском.
- Поиск в списках мероприятий, черновиков, людей и отзывов сопоставляет
  буквальные подстроки без учёта регистра.

## [0.3.0] — 2026-11-18

- Backend с PostgreSQL запущен в составе платформы; бот использует внутренний API.
- Реализованы admin API мероприятий, публикаций, медиа и отзывов,
  статистика участников, настройки ИИ и история тем.
- Логика мероприятий и публикаций общая для бота и miniapp.
- Добавлены настройка черновиков, защищённый доступ к медиа и единый
  список мероприятий и черновиков с серверной пагинацией.
- Подготовлены импорт SQLite, миграции, OpenAPI, unit- и PostgreSQL-тесты.
- Мигратор читает только DATABASE_URL и не требует targets.json или настроек ИИ.

[Общая история платформы](https://github.com/jpegMushrum/hikari-secretary/blob/main/CHANGELOG.md).

## [0.3.0-dev] — 2026-10-29

### Добавлено

- Первый предметный срез: схема PostgreSQL для людей, Telegram-идентичностей,
  мероприятий, регистраций, посещаемости, отзывов, outbox и аудита.
- Закрытый Bot API для профиля, мероприятий, регистраций, посещаемости, отзывов,
  напоминаний и статистики.
- Read-only dry-run и явный идемпотентный `--apply` импортёр текущей SQLite-схемы.
- Закрытый endpoint `POST /internal/bot/v1/people/identity`: бот может
  безопасно синхронизировать Telegram-идентичность человека.
- Административный `GET /api/v1/admin/people` с белым списком фильтров,
  сортировок и размеров страницы `10`, `20`, `30`.

### Безопасность

- Межсервисные запросы требуют отдельный `BOT_SERVICE_TOKEN` в заголовке
  `Authorization: Bearer …`; токен Telegram-бота для них не используется.

## [0.2.0-dev] — 2026-10-28

### Добавлено

- Проверка подписи и срока действия `Telegram.WebApp.initData` по официальному
  алгоритму Telegram.
- Начальная роль администратора: список разрешённых Telegram ID задаётся через
  `ADMIN_TELEGRAM_IDS`.
- Закрытый диагностический endpoint `GET /api/v1/admin/me` для проверки
  интеграции Mini App. Он возвращает данные только подписанному администратору.

### Безопасность

- API отклоняет отсутствующие, изменённые и устаревшие Telegram credentials с
  `401`, а подписанных пользователей вне списка администраторов — с `403`.
- PostgreSQL и API по-прежнему привязаны только к loopback-интерфейсу хоста.

## [0.1.0-dev] — 2026-10-27

### Добавлено

- Каркас Go backend с HTTP health endpoints.
- Docker Compose с PostgreSQL, мигратором и API.
- Версионируемые SQL-миграции и начальный OpenAPI-контракт.
