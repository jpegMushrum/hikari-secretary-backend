# API участника

Маршруты под `/api/v1/member` требуют заголовок
`Authorization: tma <исходная строка Telegram.WebApp.initData>`.
Backend определяет участника по подписанному Telegram ID.
`GET /me` возвращает данные текущего пользователя и признак `is_admin`.
Признак позволяет показать переключатель режимов. Доступ к Admin API
проверяется самим Admin API.

## Тайный Санта

`GET /santa/visibility` даёт состояние сезонного пункта меню.
`GET /santa` возвращает открытый сезон и данные текущего участника.
После утверждения жеребьёвки поле `recipient` содержит данные только
текущего подопечного участника: имя, пожелания, `telegram_id` и `username`
(имя пользователя в Telegram или `null`). До утверждения жеребьёвки
назначение и контакт скрыты. При отсутствии сезона в состоянии `open` запрос
`GET /santa` возвращает `404`.
Поле `draft_wishes` содержит личный черновик текущего пользователя или
пустую строку. Черновик возникает при отмене участия и доступен только
пользователю, который его сохранил.

`POST /santa` принимает `season_id` и команду для текущего участника.
`join` и `cancel` действуют до окончания записи и утверждения жеребьёвки.
`cancel` удаляет заявку и сохраняет последние отправленные пожелания в
`draft_wishes`. При повторной записи `join` принимает текст пожеланий,
создаёт заявку и очищает черновик. `wishes` меняет пожелания действующей заявки.
После утверждения жеребьёвки `attendance` принимает `yes` или `no`,
а `gift` принимает `recipient_id` текущего получателя и один из статусов:
`ready` («Подарок готов»), `ordered` («Подарок заказан (в пути)»)
или `not_ready` («Нет»). До ответа API возвращает `unknown`.
Ответ `not_ready` описывает текущую готовность подарка и сохраняется
без уведомления организаторов.
Команда `gift_description` принимает тот же `recipient_id` и строку
`gift_description` длиной до 2000 символов Unicode. Пустая строка
очищает описание. Оно сохраняется независимо от готовности подарка и
присутствия на обмене. При смене получателя описание остаётся у дарителя,
а статус готовности сбрасывается в `unknown`. Запрос `attendance`
для действующей заявки до утверждения возвращает `409`.
`request_exit` и `retract_exit` управляют запросом на выход. Назначение
продолжает действовать до подтверждения исключения администратором.
[Схемы запросов и ответов](../openapi/openapi.yaml).

## Мероприятия и запись

- `GET /events` отдаёт страницу доступных встреч с личным статусом.
  `view=upcoming` показывает предстоящие активные встречи,
  `view=registered` оставляет предстоящие встречи со своей записью,
  `view=all` включает архив и по умолчанию показывает новые встречи первыми.
  Поиск работает по названию и ID.
- `GET /events/{id}` возвращает карточку, опубликованный анонс при наличии,
  ссылку на сообщение Telegram, признаки доступных действий и допустимые
  варианты напоминаний. `reminder_offset_minutes` описывает текущую запись,
  `preferred_reminder_offset_minutes` — настройку для будущих встреч.
  Медиа загружаются через авторизованный
  `GET /events/{id}/media/{position}`, индексы начинаются с нуля.
  Анонс содержит только поля для показа участнику. Служебные данные публикации
  остаются в backend.
- `POST /events/{id}/registration` записывает участника на опубликованную
  встречу до её начала. Передайте `reminder_offset_minutes` в минутах
  или `null` для записи без напоминания. При незаполненной анкете передайте
  объект `profile` с обязательными полями. Профиль и запись сохраняются
  вместе. Без анкеты backend отвечает `409 profile_incomplete`. Эта операция
  сохраняет напоминание для конкретной встречи, сохраняя прежнюю настройку
  для будущих записей.
- `PATCH /events/{id}/registration` атомарно меняет напоминание текущей записи
  и настройку для будущих встреч. `DELETE /events/{id}/registration`
  отменяет запись. Оба действия доступны до начала встречи.
- `PUT /events/{id}/attendance` с булевым `attended` сохраняет первый
  ответ зарегистрированного участника после завершения встречи. Если ответ
  уже пришёл через бота или miniapp, API возвращает `409 attendance_unavailable`.

## Профиль и отзывы

- `GET /profile` отдаёт свою анкету и `reminder_offset_minutes` для будущих
  встреч. Для `PUT /profile` обязательны
  ФИО (`full_name`, от 2 до 160 символов после обрезки пробелов),
  гражданство РФ (`is_russian_citizen`) и статус студента ИТМО
  (`is_itmo_student`). Необязательный `feedback_enabled` управляет
  предложением оставить отзыв после посещения.
- `PATCH /profile` принимает булевый `feedback_enabled`, настройку
  `reminder_offset_minutes` или оба поля. Для напоминания передайте значение
  из `REMINDER_OPTIONS_MINUTES` либо `null`, чтобы выключить напоминания при
  будущих записях. Самостоятельно отправить отзыв можно при любом значении
  `feedback_enabled`.
- `GET /feedback` возвращает страницу своих отзывов.
  `POST /feedback` принимает `text` от 1 до 3000 символов после обрезки
  пробелов. Отзыв с `event_id` требует действующей записи участника на
  завершившуюся встречу. Для отменённой встречи API возвращает `404 not_found`,
  как и при отсутствии подходящей записи. Пропуск или `null` в `event_id`
  создаёт общий отзыв, который можно отправить в любое время.
  `DELETE /feedback/{id}` удаляет свой отзыв.

## Выборы маскота

`GET /api/v1/member/mascot/visibility` возвращает видимость пункта меню. Пока открыт приём концептов, поле `submission_until` содержит дату и время его окончания в формате RFC 3339.
`GET /api/v1/member/mascot` возвращает состояние сезона с учётом этапа:
свои заявки во время приёма, текущую карточку во время голосования или
итоги после публикации. Порядок карточек в бюллетене закрепляется при
старте тура и сохраняется между запросами.

`GET /api/v1/member/mascot/results/entries/{id}` возвращает анонимную
карточку концепта из завершённого или отменённого тура опубликованного
сезона. Карточка содержит название, описание, статус допуска и ключи
изображений с отметками ИИ. До публикации или после архивирования сезона
этот запрос возвращает `404 not_found`.

`POST /api/v1/member/mascot` принимает `season_id`, текущий номер `round`
и команду `submit`, `withdraw`, `ready` или `vote`. Для загрузки JPEG
или PNG отправьте файл телом запроса
`POST /api/v1/member/mascot/images?season_id=...`. Ответ содержит ключ,
который передаётся в заявке с отметкой ИИ. Изображение доступно через
`GET /api/v1/member/mascot/images/{key}` в пределах прав участника и
текущего этапа.

Во время приёма поле `pending_images` содержит ключи своих загруженных
изображений без заявки. Чтобы освободить такую загрузку, отправьте
`DELETE /api/v1/member/mascot/images/{key}`. Изображения в сохранённых
заявках меняются через редактирование самой заявки.

Форматы запросов, параметры пагинации и коды ошибок описаны в
[OpenAPI](../openapi/openapi.yaml).
