# API участника

Маршруты под `/api/v1/member` требуют заголовок
`Authorization: tma <исходная строка Telegram.WebApp.initData>`.
Backend определяет участника по подписанному Telegram ID.
`GET /me` возвращает данные текущего пользователя и признак `is_admin`.
Признак позволяет показать переключатель режимов. Доступ к Admin API
проверяется самим Admin API.

## Мероприятия и запись

- `GET /events` отдаёт страницу доступных встреч с личным статусом.
  `view=upcoming` показывает предстоящие активные встречи,
  `view=registered` оставляет предстоящие встречи со своей записью,
  `view=all` включает архив и по умолчанию показывает новые встречи первыми.
  Поиск работает по названию и ID.
- `GET /events/{id}` возвращает карточку, опубликованный анонс при наличии,
  ссылку на сообщение Telegram, признаки доступных действий и допустимые
  варианты напоминаний. `reminder_offset_minutes` описывает текущую запись,
  `preferred_reminder_offset_minutes` — настройку для будущих встреч.
  Медиа загружаются через авторизованный
  `GET /events/{id}/media/{position}`, индексы начинаются с нуля.
  Анонс содержит только поля для показа участнику. Служебные данные публикации
  остаются в backend.
- `POST /events/{id}/registration` записывает участника на опубликованную
  встречу до её начала. Передайте `reminder_offset_minutes` в минутах
  или `null` для записи без напоминания. При незаполненной анкете передайте
  объект `profile` с обязательными полями. Профиль и запись сохраняются
  вместе. Без анкеты backend отвечает `409 profile_incomplete`. Эта операция
  сохраняет напоминание для конкретной встречи, сохраняя прежнюю настройку
  для будущих записей.
- `PATCH /events/{id}/registration` атомарно меняет напоминание текущей записи
  и настройку для будущих встреч. `DELETE /events/{id}/registration`
  отменяет запись. Оба действия доступны до начала встречи.
- `PUT /events/{id}/attendance` с булевым `attended` сохраняет первый
  ответ зарегистрированного участника после завершения встречи. Если ответ
  уже пришёл через бота или miniapp, API возвращает `409 attendance_unavailable`.

## Профиль и отзывы

- `GET /profile` отдаёт свою анкету и `reminder_offset_minutes` для будущих
  встреч. Для `PUT /profile` обязательны
  ФИО (`full_name`, от 2 до 160 символов после обрезки пробелов),
  гражданство РФ (`is_russian_citizen`) и статус студента ИТМО
  (`is_itmo_student`). Необязательный `feedback_enabled` управляет
  предложением оставить отзыв после посещения.
- `PATCH /profile` принимает булевый `feedback_enabled`, настройку
  `reminder_offset_minutes` или оба поля. Для напоминания передайте значение
  из `REMINDER_OPTIONS_MINUTES` либо `null`, чтобы выключить напоминания при
  будущих записях. Самостоятельно отправить отзыв можно при любом значении
  `feedback_enabled`.
- `GET /feedback` возвращает страницу своих отзывов.
  `POST /feedback` принимает `text` от 1 до 3000 символов после обрезки
  пробелов. Отзыв с `event_id` требует действующей записи участника на
  завершившуюся встречу. Для отменённой встречи API возвращает `404 not_found`,
  как и при отсутствии подходящей записи. Пропуск или `null` в `event_id`
  создаёт общий отзыв, который можно отправить в любое время.
  `DELETE /feedback/{id}` удаляет свой отзыв.

Форматы запросов, параметры пагинации и коды ошибок описаны в
[OpenAPI](../openapi/openapi.yaml).
